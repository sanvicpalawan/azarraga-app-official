# Flow audit — 4 November 2026

Scope: current `main` (`8524024`) plus the explicitly local, uncommitted preview; no Phase 2 implementation preceded this audit. Read ARCHITECTURE.md, HANDOFF.md, README.md, both storage layers, the editor/admin components and all 24 API route files. The architecture/handoff describe an older app. Local app exercised with no database; the catalog uses memory, whereas document pages originally crashed without `DATABASE_URL`. The current preview supplies clearly labelled read-only fixtures.

**Actual flow.** `/` redirects to `/quotes`, which lists saved normalized documents. `/quotes/new` collects customer/project once, then multiple editable lines, copied/removed lines, alternative sections, live totals, manual rates/discounts and terms. Saving opens `/quotes/[id]`, with edit, duplicate, mark-sent, share/PDF and invoice-conversion controls. `/invoices` and detail/payment screens already exist. Separately, `/catalog` still runs the older state-based chooser → configure → multi-line review/print/save flow, plus projects, library, studio and admin. Customer details there are entered at review, not configuration. Projects/imported PDFs can supply reusable products/prices. Admin remains accessible inside this staff workspace; `/admin/settings` separately edits document settings.

**Assumptions corrected.** A quote is no longer limited to one item: legacy `quotations.item` supports a JSON array, and the newer `clients → documents → document_sections → document_lines` model is relational and supports alternatives. Quotes can be reopened in `/quotes/[id]`; customers exist as `clients`, but have no reusable picker/list UI. Routes, invoices, PHP/USD/EUR settings, WhatsApp summary links and PDF downloads already exist. There is no enforced staff/admin authentication. Creating a third independent quote database would fragment current live data; Phase 2 should extend the normalized model and expose the requested customer/quote names compatibly, preserving legacy records.

**Pricing and units.** Legacy series/glass/color/lock are descriptive labels: only manually entered rate × area/quantity, delivery and discount affect price. Its dimension math treats width/height as feet. New editor option snapshots can carry flat price adjustments, but base prices remain manual; its UI forces per-set pricing even when reopening per-area lines, so a save can change their meaning. It stores mm but accepts only metres. Studio supports m/mm/fractional ft-in. Neither catalog nor schema supplies reliable Category → Type → Series relationships; keep existing products and defer that hierarchy/pricing rules until real documents establish it.

**Dead ends/data loss.** Two quotation engines produce disconnected lists, settings and numbering. Legacy preview saves but cannot directly reopen that record for editing. Reload loses every unsaved legacy screen/configuration/customer/line, the newer editor draft, and unsaved studio drawing; memory data also disappears on server restart. Duplicate originally navigated to a blank new form; the pending local fix opens the returned ID. Studio export originally required a successful product save. Status/convert actions can act on saved data while edits remain unsaved; arbitrary status strings are accepted server-side. PDF/share use saved data only. Public share acceptance writes through the same unauthenticated document API. Auth must distinguish read-only sharing from staff mutations.

**Unauthenticated writes (all applicable methods).** POST `/api/products`, `/categories`, `/attributes`, `/media`, `/projects`, `/projects/extract`, `/quotations`, `/documents`, `/designs/publish`, `/admin/settings/logo`; PUT `/api/products/[id]`, `/categories/[id]`, `/attributes/[id]`, `/designs`, `/documents/[id]`, `/settings/company`, `/admin/settings`; DELETE `/api/products/[id]`, `/categories/[id]`, `/attributes/[id]`, `/media/[id]`, `/projects/[id]`, `/designs/[id]`; POST/PUT/DELETE `/api/products/[id]/image`; POST `/api/documents/[id]` (duplicate, convert, status, acceptance and payments). Local preview blocking is not production authentication. GET share rendering also marks viewed, so it needs review when making public links read-only.
